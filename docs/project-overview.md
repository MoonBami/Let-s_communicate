# 「소통해요」 프로젝트 정리 (다른 채팅용 컨텍스트)

> 교사 민원 보조 AI 시스템. 이 문서는 지금까지 논의·결정된 내용을 요약한 것으로,
> 다른 대화(챗)에서 붙여넣어 맥락으로 사용하기 위한 핸드오프 문서입니다.

---

## 1. 프로젝트 개요

**앱 이름:** 소통해요

**목적:** 교권 침해·악성 민원 문제를 완화하기 위한 교사 민원 보조 AI 시스템.

**핵심 아이디어:** 학부모 민원이 교사에게 직접 전달되지 않고 **플랫폼을 한 번 거친다.**
AI가 민원을 자동 분류·필터링하여 '정당하고 합당한 민원'만 교사에게 전달하고,
단순 행정·반복 문의는 챗봇이 자동 응대하며, 욕설·위협성 민원은 걸러내고 증거로 기록한다.

**해결하려는 문제**
- 반복 민원과 감정 소모로 인한 교사 업무 피로도
- 민원 기록 관리·공식 답변 작성에 드는 과도한 행정 시간
- 교사 실제 연락처 노출로 인한 사생활 침해 및 시간 외 연락 부담
- 악성·위협성 민원에 대한 증거 확보·대응 체계 부재

## 2. 통합 기능 정의 (F1~F9)

기존 핵심 기능 6개 + 추가 제안 5개에서 중복(민원 자동 분류, 답변 템플릿)을 통합해 9개로 정리.

| ID | 기능 | 설명 |
|----|------|------|
| F1 | 민원 자동 분류 & 지능형 라우팅 | '단순 행정 / 학습 지도(생활·성적) / 학교폭력·분쟁' 자동 분류. 단순 행정은 챗봇 자동 응대, 그 외는 필터링 후 정당한 민원만 교사 전달 |
| F2 | 감정 분석 · 위험 민원 탐지 | 민원의 감정/공격성 분석 → 위험 민원 자동 탐지·우선순위 |
| F3 | 욕설·위협 필터링 & 증거 기록 | 욕설·협박성 발언 차단(교사 미노출), 원문은 증빙용 보관 |
| F4 | 공식 답변 초안 생성 & 상담 템플릿 | 정중한 답변 초안 자동 생성 + 표준 문장 템플릿 |
| F5 | 유사 사례 검색 & 대응 추천 | 과거 민원 사례 의미 기반 검색(RAG) |
| F6 | 안심번호 & 예약 상담 | 교사 실번호 비노출 통화·채팅, 근무시간 외 알림 자동 차단, 상담 예약 |
| F7 | 실시간 녹음 & 텍스트 변환(STT) | 통화·상담 녹음 → 대화록 자동 변환(증빙) |
| F8 | 민원대응팀(MDT) 이관 연동 | 버튼 하나로 관리자·MDT에 즉시 이관 |
| F9 | 관리자 통계 대시보드 | 민원 유형·건수·위험도·대응 현황 시각화 |

**우선순위:** MVP = F1·F4·F9 → 2차 = F2·F3·F5·F8 → 3차 = F6·F7 (+선택적 모바일 앱)

## 3. 확정된 주요 결정

- **플랫폼:** **웹(반응형) 우선 개발로 확정.** 교사·학부모·관리자를 하나의 반응형 웹으로 커버.
  학부모 앱 설치 강제 없음(진입장벽↓), 프론트 1명 구성에 현실적. 모바일 앱은 통화·녹음·푸시가
  필요한 3차에서 교사용으로만 선택적 도입(React Native).
- **팀 구성:** **AI/ML 1명 · 프론트엔드 1명 · 백엔드 2명 (총 4명).**
- **AI 방식:** 초기에는 **상용 LLM API(Claude/GPT 등)**로 시작. 자체 모델 학습은
  데이터가 충분히 쌓여 비용/정확도 이점이 분명해질 때 파인튜닝 검토.

### 인력 역할 분담
| 역할 | 담당 범위 | 주요 업무 |
|------|-----------|-----------|
| AI/ML (1) | F1·F2·F3·F4·F5·F7의 AI 로직 | 분류·감정·욕설 프롬프트 설계, RAG 파이프라인, STT 연동, 품질 평가·가드레일 |
| 프론트엔드 (1) | 반응형 웹 전체 | 교사 민원함, 학부모 접수 화면, 관리자 대시보드(F9), 채팅 UI |
| 백엔드 A (1) | 코어 서비스 | API·인증·권한, DB 스키마, 민원 라우팅/필터 로직, MDT 이관(F8) |
| 백엔드 B (1) | 인프라·연동 | 배포·CI/CD, 비동기 큐, 안심번호·통화 연동(F6), AI 서빙 지원 |

> **리스크:** AI 담당 1명은 단일 장애점(SPOF) → RAG·API 연동 지식을 백엔드 B와 공유해 이중화.

## 4. 기술 스택

### 프론트엔드 (웹 우선)
- **React 18 + TypeScript + Vite**
- UI: Tailwind CSS + shadcn/ui
- 반응형 + **PWA**(홈 화면 추가·기본 웹 푸시로 앱 유사 경험)
- 상태/데이터: TanStack Query + Zustand
- 폼/검증: React Hook Form + Zod
- 차트: Recharts (대시보드 F9)
- 실시간: Socket.IO(채팅) / WebRTC(웹 통화)
- 모바일 앱(3차·선택): React Native (Expo)

### 백엔드
- **Python + FastAPI** (AI 연동 유리, 비동기, 자동 OpenAPI 문서)
- ORM/마이그레이션: SQLAlchemy + Alembic
- 인증: OAuth2 + JWT (교사/학부모/관리자/MDT 역할 분리, 교원 인증 연동 고려)
- 비동기 작업: Celery + Redis (STT 변환, 배치 분석)
- 검증: Pydantic v2
- (대안: Node.js + NestJS — 단 AI 라이브러리는 Python 우세)

### AI / ML
| 기능 | 방식 |
|------|------|
| 민원 분류(F1) | LLM API few-shot 우선 → 데이터 축적 후 KoELECTRA/KcBERT 파인튜닝 |
| 감정/위험(F2) | 한국어 감정·혐오표현 모델 + LLM 보조 |
| 욕설 필터(F3) | 욕설 사전 + 형태소 분석(Kiwi/soynlp) + 분류 모델 (규칙+ML 하이브리드) |
| 답변 초안(F4) | LLM + 프롬프트 템플릿 + RAG |
| 유사 사례(F5) | 임베딩(ko-sroberta / OpenAI embeddings) + 벡터 검색, LangChain/LlamaIndex |
| STT(F7) | CLOVA Speech / faster-whisper / RTZR (한국어는 CLOVA·리턴제로 정확도 우수) |

**AI 난이도 메모:** '모델 직접 학습'은 어렵지만, 상용 API 활용 시 'AI 개발 = 프롬프트 설계 + API 연동
+ 파이프라인 구축'에 가까워 난이도가 크게 낮아짐. 초기엔 자체학습 금지, API로 시작.
정확도보다 **틀렸을 때의 안전장치(사람 재검토·이의제기 경로 F8)**가 더 중요.

### 데이터 · 인프라
- 메인 DB: **PostgreSQL** (15+)
- 벡터 검색: **pgvector**(초기) → Qdrant(확장 시)
- 캐시/큐: Redis
- 파일 스토리지: S3 호환(AWS S3 / NCP Object Storage), 녹음 암호화 저장
- 배포: Docker + (AWS ECS 또는 NCP). 교육·공공 데이터 특성상 국내 클라우드(NCP) 검토 권장
- CI/CD·모니터링: GitHub Actions + Sentry
- 안심번호(F6): 통신사 050 / 제3자 안심번호 API (자체 구현 불가 → 외부 연동)

## 5. 시스템 아키텍처 (게이트웨이 구조)

```
학부모 민원 입력 → [플랫폼: AI 필터·분류] → 정당한 민원만 교사 전달
```
1. **접수 계층** — 웹/앱에서 학부모가 민원 입력 또는 안심번호로 통화·채팅
2. **AI 처리 계층** — 분류(F1) → 감정/위험(F2) → 욕설 필터(F3). 단순 행정은 챗봇 자동 응대, 위협성은 차단·기록
3. **교사 계층** — 필터 통과한 정당한 민원만 전달. 답변 초안(F4)·유사 사례(F5) 지원
4. **관리 계층** — MDT 이관(F8), 녹음·대화록 증빙(F7), 통계 대시보드(F9)

## 7. 법적 · 보안 · 윤리 (필수 검토)

- **통화 녹음(F7):** 통신비밀보호법상 대화 당사자 녹음은 가능하나, 상대방 사전 고지(안내 멘트) 권장
- **개인정보보호법:** 민원 내용·녹음·학생/학부모 정보는 민감정보 준하여 암호화 저장, 보관기간·파기 정책, 수집·이용 동의 필요
- **안심번호(F6):** 실번호 비노출은 통신사/제3자 가상번호 중계로만 구현 가능 → 사업자 계약·비용 사전 확인
- **AI 판단의 한계:** 자동 필터가 정당한 민원을 잘못 차단하지 않도록 사람 재검토·이의/에스컬레이션 경로(F8) 필수
- **데이터 주권:** 교육·공공 성격상 국내 리전/클라우드 우선 검토

## 8. DB 스키마 요약

PostgreSQL 15+ / pgvector 기준. 전체 DDL은 별도 `sotonghaeyo_schema.sql` 참조.

**주요 테이블**
- 조직·사용자: `schools`, `users`, `teacher_profiles`(근무시간·차단), `students`, `guardianships`, `teacher_assignments`
- 민원: `complaints`, `complaint_messages`
- AI 처리: `classifications`(F1), `risk_analyses`(F2), `content_filter_logs`(F3, 증거 보관)
- 답변: `response_templates`(F4 템플릿), `answer_drafts`(F4)
- 유사 사례: `complaint_cases`, `case_embeddings`(pgvector, F5)
- 통화/예약: `safe_numbers`, `consultation_reservations`, `call_sessions`(F6)
- 녹음: `recordings`, `transcripts`(F7)
- 이관: `escalations`(F8)
- 운영: `notifications`, `audit_logs`
- 대시보드: `v_complaint_stats`, `v_teacher_workload` (뷰, F9)

**주요 ENUM:** `user_role`, `complaint_category`, `complaint_status`, `risk_level`, `escalation_status`, `reservation_status`, `call_status`

> 임베딩 차원은 `VECTOR(1536)`(OpenAI 임베딩 기준). 다른 한국어 임베딩 모델 사용 시 차원 조정 필요.
