## 1. 한 줄 요약

**게이트웨이 파이프라인이 접수부터 종결까지 엔드투엔드로 동작한다.**

F7은 변환 파이프라인만, F6은 미착수.

단, **AI가 실제 Claude API로 돌아간 적은 아직 없다.** 지금까지 검증된 것은 전부
규칙 기반 fallback 경로다. (F3 욕설 필터는 애초에 규칙 기반이 최종 경로라 예외)

| 결과 | `complaints.status` | 처리 |
|------|---------------------|------|
| 욕설·위협 감지 | `filtered_blocked` | 교사 미노출, 원문을 `content_filter_logs.raw_evidence`로 증거 보관 |

### 자동 응대 게이트 (`services/ai/gate.py`)

오분류 비용이 비대칭이라 자동 응대 쪽으로만 보수적으로 판정한다.
학교폭력 민원을 '단순 행정'으로 오분류하면 자동 응대되고 교사에게 영원히 가지 않는데,
반대 방향 오류는 교사가 한 번 더 보는 것으로 끝난다.

네 조건을 **모두** 통과해야 자동 응대한다.

| # | 조건 | 이유 |
|---|------|------|
| 1 | 단순 행정으로 분류됨 | 자동 응대 대상 카테고리 |
| 2 | 자동 응대 금지 신호 없음 | 결정론적 키워드 안전망 (학폭·자해·성 관련·학대) |
| 3 | 위험도가 `high`/`critical` 아님 | F2 교차 검증 |
| 4 | 분류 신뢰도 ≥ `AUTO_ANSWER_MIN_CONFIDENCE` | 확신 없으면 사람에게 |

2번이 규칙 기반인 이유는 F3와 같다. 아동 안전 판정을 확률적 모델에만 맡기지 않는다.
또한 F2는 *공격성*을 보므로 **차분하게 서술된 심각한 사안**은 위험도가 낮게 나온다 —
"아이가 자해를 해서 상담 서류를 신청하고 싶습니다"는 F1이 `administrative`,
F2가 `low`로 판정하지만 2번이 막는다. 실측으로 확인된 동작이다.

### F3 오차단 수정 (2026-08-10)

F3 필터에 회귀 테스트를 붙이는 과정에서 **정당한 민원 10종이 차단되고 있었다.**
차단된 민원은 교사에게 가지 않고 admin·mdt만 열람할 수 있어 되돌릴 경로가 없다.

| 패턴 | 오차단된 정당한 민원 | 심각도 |
|------|---------------------|--------|
| `때려` | "친구가 아이를 **때려서** 팔에 멍이 들었습니다" | 🔴 학폭 신고가 사라짐 |
| `두들겨` | "아이가 **두들겨 맞았다**고 합니다" | 🔴 피해 신고가 사라짐 |
| `찾아가서` | "학교에 **찾아가서** 상담하고 싶습니다" | 방문 상담 요청 |
| `꺼져`/`꺼지` | "교실 난방이 **꺼져** 있어서" | 시설 민원 |
| `닥쳐`/`닥치` | "제출 기한이 **닥쳐서** 급하게" | 행정 문의 |
| `새끼` | "아이가 **새끼손가락**을 다쳐서" | 부상 문의 |
| `정신병` | "아이가 **정신병원**에서 상담 치료를" | 민감·차별적 |

폭력을 *신고하는* 민원은 가해 표현과 어휘가 겹친다. 어휘 하나만 보고 차단하면
**이 서비스가 막으려는 문제를 필터가 만들어낸다.** 수정 방향은 가해 의도가 드러나는
연결형까지 함께 요구하는 것이다(`때려죽`·`때려버`·`두들겨패`는 차단, `때려서`는 통과).
일상 어휘와 겹치는 표현은 부정 탐색으로 제외했다(`이/가` + `꺼져` = 사물 주어).

같은 작업에서 **게이트 구멍**도 발견했다. `VIOLENCE_KEYWORDS`에 `때리`만 있고
활용형(`때려`·`때렸`·`맞았`)이 없어서, "아이가 때려서 다쳤는데 보험 **서류 신청**
방법을 알고 싶습니다" 같은 문장이 뚫렸다. fallback 신뢰도가 0.4라 우연히 막혀
있었을 뿐, **실제 LLM이 0.95로 분류하면 학폭 신고가 자동 응대된다.** 활용형을
보강하고 게이트에는 피해·부상 서술(`맞았`·`다쳤`·`멍이`)까지 넣었다.

분류기와 게이트의 목록을 분리한 이유는 목표가 다르기 때문이다 — 분류기는 정확도
(오탐이면 잘못된 라벨이 보인다), 게이트는 누락 방지(오탐이면 교사에게 한 번 더 갈 뿐).
게이트 목록이 분류기 목록을 **포함하고 더 넓다**.

> ⚠️ **기본값(0.7)에서는 fallback 분류기로 자동 응대가 발생하지 않는다.**
> 규칙 기반 분류기가 신뢰도 0.4를 반환하기 때문 — 키워드 매칭만으로 자동 응대하지
> 않겠다는 의도된 동작이다. 실제 LLM을 붙이면 자동 응대가 살아난다.
> 데모에서 자동 응대를 보여줘야 하면 `AUTO_ANSWER_MIN_CONFIDENCE=0.3`으로 낮출 수 있다.

## 5. 검증 기록 (2026-08-06 ~ 08-10)

### 단위 테스트 — 149건 통과 / 0건 실패 (리포에 커밋됨)

`cd backend && pytest`. DB·네트워크 연결 없이 0.5초에 돈다.

**자동 응대 게이트 30건** — '단순 행정 + 신뢰도 1.0 + 위험도 low'라는 최악의 조합으로
들어온 학폭·자해·성 관련·학대 문장이 전부 차단되는지. 과잉 차단 방지도 함께 고정.

**F3 필터 72건** — 통과(오차단 방지) 케이스를 차단 케이스보다 촘촘히 깔았다.
필터를 테스트하며 **오차단 10건과 게이트 구멍 1건을 발견해 수정**했다(§F3 오차단 수정).

**합성 데이터 생성기 32건** — 생성기와 분류기의 카테고리 목록 일치, 라벨 이탈·지시문
유출·중복 판정·결정론적 분할·응답 파싱.

**평가 하네스 15건** — 정밀도·재현율·F1·macro F1·혼동행렬을 손계산 예시로 고정하고,
치명 오류 집계의 방향성(학폭→행정은 치명, 학폭→생활은 아님)을 고정.

게이트에서 막혀 `pending_teacher`로 갔고, 보류 근거가 로그에 남았다
(`분류 신뢰도 부족(0.40 < 0.70)`, `자동 응대 금지 신호 감지: 자해`).
임계값을 0.3으로 낮추면 평범한 행정 민원이 `auto_answered`로 정상 동작.

**일회성 스크립트로 수행했고 커밋되지 않았다.** FastAPI `TestClient` + 테스트 DB로
옮기는 작업이 필요하다.

### 6-2. 챗봇 자동 응대가 실체가 없다

단순 행정 민원이 `auto_answered` 상태만 기록되고 **응대 문구가 어디에도 남지 않는다.**
`complaint_messages` 테이블은 스키마에 있으나 ORM 모델조차 없다.

결과적으로 학부모 입장에서는 "자동 응대 완료"인데 답을 받지 못한다.
F1 기획("단순 행정은 챗봇 자동 응대")과 실제 동작이 어긋나 있다.

### 6-3. 학부모가 자기 민원을 조회할 수 없다

접수 API(`POST /api/complaints`)가 `parentId`를 받지 않고 `complaints.parent_id`를
채우지 않는다 → 사실상 익명 접수.

학부모 계정으로 로그인은 되지만 민원함은 403이므로 **로그인 후 갈 곳이 없다.**
`guardianships`(보호자-학생 관계) 테이블도 미사용.

### 6-4. F4 표준 문장 템플릿 미구현

`response_templates` 테이블 미사용. 현재는 순수 LLM 생성이라
기획의 "상담 템플릿 / 표준 문장" 요건이 빠져 있다.
`answer_drafts.template_id`·`is_adopted`·`edited_body` 컬럼도 채워지지 않는다
(초안 채택·수정 저장 기능 없음).

### 6-5. `audit_logs`가 비어 있다

차단 민원 증거 열람을 admin·mdt로 제한하긴 했으나 **누가 언제 열람했는지 기록하지 않는다.**
기획 문서상 민감정보 접근 추적은 필수 항목이다.

### 6-6. Alembic 미도입

스키마 변경 수단이 컨테이너 재생성뿐이다. 팀원이 각자 DB를 쓰기 시작하면 곧 어긋난다.
운영 전환 전 필수.

### 6-7. 기타

- 프론트 번들 726KB (Recharts 포함) — 코드 스플리팅 미적용
- 접수 응답이 AI 호출(F1·F2)을 동기로 기다림 — Claude 붙이면 응답 지연 체감
- `teacher_profiles` 근무시간 외 알림 차단 로직 미구현, `notifications` 미사용
- `MIN_SIMILARITY = 0.2` 임계값은 **해싱 임베딩 기준으로만 관찰**됨.
  실제 임베딩 API 도입 시 재조정 필요

## 7. 자체 모델(F1) 준비 상태

기획 문서의 "데이터 축적 후 KoELECTRA/KcBERT 파인튜닝" 경로를 위한 기반이 깔렸다.

| 단계 | 상태 | 도구 |
|------|------|------|
| 안전장치 | ✅ | `services/ai/gate.py` — 모델이 틀려도 위험 민원이 자동 응대되지 않게 |
| 라벨 데이터 생성 | ✅ | `scripts/gen_synthetic_complaints.py` |
| 평가 기준 정의 | ✅ | `scripts/eval_classifier.py` — 정확도 + **안전 지표** |
| 기준선 측정 | ✅ | 아래 기록 — 새 모델이 넘어야 할 숫자 |
| 모델 학습 | ⛔ | AI/ML 담당 영역 |

#### 기준선 — 규칙 기반 `keyword-fallback` (2026-08-10)

합성 평가셋 53건, `gemma3:4b` 생성. **새 모델은 이 숫자를 넘어야 한다.**

| 지표 | 값 |
|------|-----|
| 정확도 | **0.717** |
| macro F1 | **0.693** |
| 치명 오류 (학폭 → 단순 행정) | **0/3 (0.0%)** |
| 최종 안전 (자동 응대될 위험 민원) | **0건** (신뢰도 0.95 가정에서도 0건) |

| 카테고리 | 정밀도 | 재현율 | F1 | 건수 |
|---|---|---|---|---|
| administrative | 1.000 | 0.700 | 0.824 | 10 |
| learning | 0.571 | 0.800 | 0.667 | 10 |
| life | 0.714 | 0.500 | 0.588 | 10 |
| grades | 1.000 | 0.800 | 0.889 | 10 |
| violence_dispute | 1.000 | **0.333** | 0.500 | **3** |
| other | 0.562 | 0.900 | 0.692 | 10 |

`administrative` 는 정밀도 1.000 / 재현율 0.700 — **약한 방향이 안전한 방향**이다.
단순 행정을 놓치면 교사에게 가지만, 반대로 잘못 넣으면 자동 응대된다.

> ⚠️ **`violence_dispute` 표본이 3건뿐이고 재현율 0.333이다.** 가장 중요한 카테고리의
> 표본이 가장 적다 — 생성기의 라벨 이탈 방어가 이 카테고리에서 특히 많이 걸러냈기
> 때문이다(gemma3:4b 가 학교폭력 소재를 요구대로 못 만드는 경우가 잦다).
>
> 놓친 2건이 `learning`·`life` 로 가서 **치명 오류는 0**이고 교사에게는 전달된다.
> 다만 교사에게 보이는 카테고리 라벨이 틀리고 F2 우선순위도 어긋난다.
> **배포 판단 전에 이 카테고리 표본을 30건 이상으로 늘려 다시 측정해야 한다**
> (`--model gemma4:12b --categories violence_dispute --count 40`).

> ⚠️ 합성 평가셋 기준이다. 실제 민원에서는 더 낮게 나올 것을 전제해야 한다.

**평가 기준을 학습보다 먼저 만든 이유**: 무엇을 잘한다고 할지 정하지 않으면 나중에
모델이 좋아졌는지 알 수 없다. 그리고 이 시스템의 지표는 정확도가 아니다 —
`eval_classifier.py` 는 ① 일반 지표 ② 치명 오류(학폭 → 단순 행정 오분류)
③ 최종 안전(게이트까지 통과해 실제로 자동 응대될 위험 민원)을 나눠 보고한다.
③이 0이 아니면 배포 불가이고, `--max-unsafe 0` 으로 CI 에 걸 수 있다.

**외부 데이터 참고**: AI Hub 「민원 업무 자동화 인공지능 언어 데이터」(100만 건,
2GB, 의도분류·개체명·부서 라벨). 지자체 민원 기준이라 카테고리 체계가 달라 F1 라벨로
직접 쓸 수는 없지만, **도메인 적응 사전학습(DAPT)** 에는 유용하다 — 라벨 데이터가
적은 지금 상황에서 정확도를 올리는 정석 경로. 내국인 신청 + 승인 절차가 필요하고,
**학습된 가중치의 배포 가능 여부는 약관 확인이 필요**하다.

## 9. 키 없이 동작하는 구조

로컬·데모에서 키 없이 앱이 뜨도록 모든 AI 경로에 fallback을 뒀다.

| 기능 | 키 있을 때 | 키 없을 때 |
|------|-----------|-----------|
| F1 분류 | Claude (`AI_CLASSIFY_MODEL`) | 키워드 규칙 (`keyword-fallback`) |
| F2 위험 | Claude | 키워드 휴리스틱 (`rule-risk-v1`) |
| F3 필터 | — | 결정론적 정규식 (`rule-filter-v1`) — 키 무관, 항상 동일 |
| F4 초안 | Claude (`AI_DRAFT_MODEL`) | 고정 템플릿 (`template-fallback`) |
| F5 임베딩 | OpenAI 호환 API (`EMBEDDING_API_KEY`) | 문자 n-gram 해싱 (`hash-embed-v1`) |
| F7 STT | CLOVA Speech | **fallback 없음 — 실패** (증빙 경로라 의도된 설계) |

F5는 두 방식의 벡터 공간이 다르므로 `case_embeddings.model_name`을 남기고
**검색 시 같은 모델의 벡터만 비교**한다. 임베딩 제공자를 바꾸면
`reindex_missing_case_embeddings`로 재인덱싱해야 한다.
